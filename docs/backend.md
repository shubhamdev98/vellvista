# VellVista Backend Workflow & Development Guide

This document describes the design, architecture, database schemas, services, and developer workflow of the **VellVista** backend Express application.

---

## 📁 Directory Structure & Modules

The backend resides in the `/backend` sub-directory of the workspace:

```

├── drizzle/                    # SQL schema files generated by Drizzle Kit
├── src/                        # Backend TypeScript source files
│   ├── services/               # Core business services
│   │   ├── productService.ts   # Product variants, categories, reviews logic
│   │   ├── razorpayService.ts  # Payment processing and webhook validation
│   │   └── userService.ts      # User queries and updates
│   ├── auth.ts                 # Better-Auth server-side config and providers
│   ├── cleanDummyData.ts       # Script to purge testing logs
│   ├── db.ts                   # Drizzle client database initializer
│   ├── index.ts                # Main Express server entrypoint
│   ├── migrate-images.ts       # Script to migrate local image paths to Cloudinary
│   ├── resetDb.ts              # Purges and recreates database tables
│   ├── schema.ts               # Core database table mapping definitions
│   ├── seed.ts                 # Seeder script populating product catalogs

├── package.json                # Dependencies, scripts, TS configurations
├── tsconfig.json               # Backend compiler config

```

## 📡 API Architecture & Routing

The backend uses a hybrid API routing mechanism:

### 1. tRPC Router (`backend/src/trpc.ts`)
We use type-safe **tRPC** queries and mutations for client operations. 
- Avoids writing traditional REST endpoints and body-parsing validation schemas.
- Express mounts the tRPC middleware at `/trpc` using `createExpressMiddleware`.
- **Procedures**:
  - `getProducts`: Fetches list of products (supports filters, categories, price range).
  - `getProductById`: Fetches specific product data along with its reviews and variants.
  - `createOrder`: Places checkout orders, calculates prices, and triggers Razorpay order identifiers.
  - `submitReview`: Processes product reviews, ratings, and triggers real-time WebSocket events.

### 2. Traditional Express REST Routes (`backend/src/index.ts`)
Standard Express paths are maintained for handling file uploads and authentication callbacks:
- `/api/auth/*`: Routed to the Better Auth node handler.
- `/api/upload-product-image`: Uploads catalog images to Cloudinary.
- `/api/upload-image`: Uploads custom image files.
- `/api/upload-video`: Uploads hero videos.
- `/api/reviews/:productId`: Fetches specific product review history.
- `/health`: Endpoint returned by containers for readiness/liveness checks.

## 🗄️ Database Mapping & ORM (Drizzle)

We use **Drizzle ORM** communicating with PostgreSQL over `postgres` driver (configured inside [backend/src/db.ts](file:///e:/program/Next.js/my-app/backend/src/db.ts)).

### Database Schemas (`backend/src/schema.ts`)
Key tables mapped inside Drizzle include:
*   `user`: User profiles, email, role (USER, ADMIN, SUPER_ADMIN), and status flags.
*   `session` & `account` & `verification`: Tables utilized by Better Auth to store OAuth tokens, active cookies, and register tokens.
*   `products`: Stores base product data, ratings, description, brand details.
*   `product_variants`: Product packaging options (e.g. 50ml vs 100ml) mapped with stock, SKU, and price.
*   `reviews`: Customer reviews and star ratings linked to users and products.
*   `orders` & `order_items`: Order history, tracking state (Pending, Shipped, Delivered), pricing details, and line item entries.

## 🔒 Authentication System (`backend/src/auth.ts`)

- Powered by **Better Auth** using session cookies.
- Express mounts the node handler: `app.all("/api/auth/*", toNodeHandler(auth))`.
- Secret tokens and cookie salts are signed using `BETTER_AUTH_SECRET`.
- Support is enabled for Google OAuth credentials (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`).
- Supports transaction mail alerts using Nodemailer configured with `SMTP_USER` and `SMTP_PASS` parameters.

## 🔌 Socket.io Real-time Communication

Backend runs a HTTP server wrapping Socket.io:
*   **Rooms**: Client browser sockets join product rooms (`socket.on('join-product', (productId) => socket.join('product-' + productId))`).
*   **Real-time Reviews**: When a new review is submitted via `/api/reviews`, the backend writes it to the database and immediately broadcasts it to the room:
    ```typescript
    io.to(`product-${productId}`).emit('new-review', formattedReview);
    ```
*   **Admin Notifications**: Submitting reviews also emits `admin-notification` events so admins see real-time updates in their dashboard.

## ⚡ Developer Execution Commands

To run the backend locally without containerization:
```bash
# Enter backend directory
cd backend

# Copy env template and configure credentials
cp .env.example .env

# Build backend dist folder
pnpm run build

# Start development watcher (using tsx watch)
pnpm run dev

# Run migrations/generate snaps
pnpm run db:generate
pnpm run db:push
```
*Note: Make sure your local PostgreSQL server is running and matches the `DATABASE_URL` configured in your `.env` file.*
